# 架构决策

## 系统边界

核心业务平台负责身份、权限、团队、会话、统计、审计和配置管理。AI 服务负责模型适配、文档处理、RAG、语音和工具运行。模型推理进程独立部署，不与任一业务服务共享运行环境。

## 身份模型

- 统一身份认证中心是账号信息的唯一来源。
- 平台以 OAuth2 `userInfo.userId` 作为外部用户唯一标识。
- 首次成功登录时即时创建影子用户，后续登录更新允许同步的资料字段。
- 平台角色、团队、资源授权和配额不回写统一身份认证中心。
- 身份中心用户被停用后，本地会话应失效，但具体同步机制需联调确认。

## 用量模型

每次模型请求写入不可变的 `usage_event`。定时聚合任务按用户和自然日更新 `daily_user_usage`。对话数按当天首次产生有效消息的会话统计，请求数按模型调用统计，两者不得混用。

Token 以推理服务返回的 usage 为准；服务不返回时由与模型匹配的 tokenizer 计算并标记为估算值。流式请求即使被用户中止，也应记录已生成的 Token 和中止状态。

## 扩展模型

- 模型：通过 OpenAI 兼容端点和模型能力声明注册。
- Skill：带版本的本地能力包，通过清单声明入口、参数和权限。
- MCP：独立进程或容器运行，通过工具网关访问。
- 智能体：引用模型、提示词、知识库和工具，不直接持有底层连接密钥。

所有工具调用必须设置超时、并发限制、文件访问范围和审计策略。高风险操作需要用户确认或人工审批节点。

## 离线交付

发布包应包含应用制品、容器镜像、数据库迁移、Python wheel、npm 产物、模型文件清单和校验值。生产环境禁止运行时访问公共软件源或模型仓库。
