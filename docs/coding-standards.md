# 代码与注释规范

## 基本原则

注释用于解释契约、原因、边界条件和非显然的实现选择，不逐行复述代码。修改行为时必须同步修改相关注释，过期注释视为缺陷。

## Java

- 公开类、record、接口和公开业务方法必须有 Javadoc。
- Controller 注释说明 HTTP 契约、权限和响应方式。
- Service 注释说明事务、异步、流式处理和失败降级边界。
- Repository 注释说明查询目的、一致性要求和所有权过滤。
- DTO 注释说明字段语义，尤其是可空字段和枚举状态。
- 私有方法仅在算法、协议解析或约束不直观时添加注释。

## Python

- 每个模块必须有模块 docstring。
- 公开类、异常、函数和异步生成器必须有 docstring。
- Provider 适配代码必须说明输入协议、输出协议、密钥边界和异常转换。
- 测试函数说明其验证的行为，不重复测试步骤。

## Vue 与 TypeScript

- 领域接口、SSE 协议和跨服务数据结构必须说明来源和用途。
- API 调用、流式解析、持久化状态和异步刷新函数必须有职责注释。
- 大型单文件组件按状态、API、交互和模板区域分区。
- 模板注释描述页面区域，不描述颜色或显而易见的标签。

## SQL 与配置

- 每个 Flyway 迁移必须说明迁移目的以及不可逆的数据语义。
- 统计表、审计表和权限字段必须说明口径或安全边界。
- 环境变量按服务分组，并注明密钥、可替换模型和离线部署要求。
- JSON 不支持注释，字段说明应放在 README 或同目录 Markdown 文档中。

## 禁止事项

- 禁止“给变量赋值”“调用某方法”等无信息量注释。
- 禁止在注释、日志、示例或测试快照中写入真实密钥和密码。
- 禁止保留与当前行为不一致的 TODO、接口说明和示例。
